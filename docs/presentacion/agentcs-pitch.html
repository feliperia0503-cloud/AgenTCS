El problema

Modernizar no es traducir sintaxis

La banca sigue corriendo sobre COBOL, PL/SQL, RPG, Delphi y .NET antiguo. La lógica real —cálculos, redondeos, caminos de error— está dispersa entre el código y el conocimiento de pocos especialistas.

🧮

El riesgo está en los decimales

Un redondeo cambiado o una regla omitida altera un cálculo financiero sin que nadie lo note.

📦

Caja negra

Traducir "a ojo" o solo con IA no deja evidencia de que el sistema nuevo se comporta igual que el viejo.

⏳

Costo de regresión

Sin pruebas diferenciales, validar la equivalencia se vuelve lento, manual y caro.

La solución

AgenTCS

Un copiloto agnóstico de lenguaje: ingiere el legacy, extrae las reglas de negocio con sus líneas de origen, exige aprobación humana, genera el código moderno y prueba la equivalencia ejecutando ambos.

Cualquier origen Cualquier destino moderno Un solo comando: Docker
  • ✓
    Especificación neutral entre origen y destino — el núcleo no conoce ningún lenguaje concreto.
  • ✓
    Equivalencia demostrable, no prometida: se compara campo por campo, con tolerancia cero.
  • ✓
    Humano en el centro: cada regla se aprueba, ajusta o rechaza antes de generar.
  • ✓
    IA responsable: se sanitizan secretos y solo se usan datos sintéticos.

El corazón: equivalencia

Tres niveles de evidencia, siempre declarados

La pantalla dice de dónde salió el resultado esperado. Nunca se presenta una referencia como si fuera el legacy real.

+ fuerte
A

Legacy ejecutado

El código antiguo corre de verdad en el contenedor (GnuCOBOL, Mono, JDK…) y su salida es la referencia.

B

Pares E/S provistos

El usuario aporta entradas y salidas esperadas. Útil cuando el legacy no se puede ejecutar, como PL/SQL sin Oracle.

C

Referencia derivada

Una implementación independiente generada desde la especificación aprobada. Se declara como la evidencia más débil.

Comparación con tolerancia cero, decimal exacto con escala y modo de redondeo explícitos. Nunca punto flotante para dinero.

Motor de autocorrección

Aprende de cada diferencia

Cuando el código generado no pasa un caso, el motor devuelve al modelo exactamente qué campo falló, el valor esperado y el obtenido, y la regla asociada. Genera una versión nueva y repite.

Para en equivalencia total o en meseta o al llegar al límite

Nunca conserva una versión peor: devuelve el mejor intento. Si un caso que ya pasaba vuelve a fallar, lo marca como regresión.

Seguridad e IA responsable

La seguridad ocurre antes de usar IA

🛡️

Sanitización

Secretos, correos y tarjetas se enmascaran antes de cualquier llamada al modelo.

🙋

Humano en el centro

Ninguna regla llega al código sin que una persona la apruebe, con su nombre en la traza.

🔒

Sin datos reales

Solo datos sintéticos. `.env` nunca se versiona; se rechazan repositorios internos o privados.

🔎

Escaneo del resultado

gitleaks y Semgrep revisan el código generado: secretos, punto flotante en dinero, eval.

Cada error que ve el usuario trae un código, un mensaje claro y una acción sugerida — nunca una traza ni contenido sensible.

Qué entrega

Un paquete, no una respuesta del modelo

Al terminar, una descarga reúne todo lo necesario para revisar y confiar en la migración.

Arquitectura técnica

Portable por diseño

Todo corre dentro de una sola imagen de contenedor. En la máquina de la demo solo hace falta Docker.

⚙️

Núcleo · Python

FastAPI, SDK de Anthropic y un motor de autocorrección propio. Lo específico de cada lenguaje vive en adaptadores.

🖥️

Interfaz · React

Asistente de 8 fases, revisión de reglas, vista comparativa legacy ↔ generado y tablero de evidencia.

🐳

Runtimes en la imagen

GnuCOBOL, Mono, JDK 21, .NET 8, Node y Python — origen y destino conviven sin instalar nada en el host.

Modo replay: la inferencia se reproduce desde una caché por hash del prompt, para una demo sin internet y sin gastar créditos.

Arquitectura

Cómo se conectan las piezas

La API y el motor nunca mencionan un lenguaje concreto: todo lo específico vive en un pack. Agregar un lenguaje de origen ejecutable es un YAML y un Markdown.
